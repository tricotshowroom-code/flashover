# FLASHOVER — session rules

This session starts fresh. There is no prior conversation, no memory of earlier decisions, and
no record of what was once considered and changed. The governing documents in this folder are
the entire authority. If something is not written in them, it is not established, and the
Writer may only propose it.

## Roles
Jason is the Judge and rules on everything. Claude is the Writer. ChatGPT audits. Grok runs the
final human-realism pass once a scene's construction and content are settled. Nothing is adopted
until Jason locks it. Locked text changes only by his explicit amendment.

## Governing documents, by domain
- FACTS, CHRONOLOGY, KNOWLEDGE ORDER, PROTECTED OUTCOMES: the current Canon file (00_Canon_*).
- PLACEMENT, SEQUENCE, AUDIENCE KNOWLEDGE, PRESSURE: the current Scene Order and Story Pressure
  Map in 08_Roadmap (highest version number governs).
- PERSONALITY, RELATIONSHIPS, SPEECH, BEHAVIOR: the current Character Voice Blueprint.
- STORY FACTS AND PAGE BUDGETS: the current Blueprint (02_Blueprint_*), superseded by the Map
  for placement.
- LOCKED TEXT: 04_Blocks. Binding. A finding against locked text is a proposed amendment only.
- WORKING DRAFTS: 07_Notes. Not adopted. Carried for structure, not as approved text.
- EVALUATION GATES: the Human Realism Dialogue Prompt (v2.7), the HEAT Pass (v1.1), and the
  Voice Blueprint pass, all run on every draft before it is presented.

Where two governing documents conflict, say so and ask Jason. Do not resolve it from memory,
inference, or anything outside this folder.

The writing-approach text supplied as system preferences is method, not canon. Where it
conflicts with the Voice Blueprint, the v2.7 prompt, or the Canon, the project documents govern.

## Standing rules
- Discuss each scene first; draft only on request; present full scenes.
- Run v2.7, HEAT and the Voice Blueprint pass before presenting; gate results first, then the
  scene, change note, evidence check, honest length.
- Repair, always repair: a REVISE is followed by the repaired draft in the same turn.
- Lengths by the project count (54 lines a page, blank line between elements, 35-character
  dialogue wrap), always labeled an estimate. Final Draft pagination UNVERIFIED unless measured.
  Never convert the project count into presumed Final Draft pages. 120 formatted pages is the target.
- Preserve prior drafts. Never alter locked blocks. Never silently change chronology or canon.
- No manufactured drift, pauses or unanswered questions to satisfy a pattern. Profiles are
  ranges, not signature moves. Wordless scenes still obey the profiles through behavior.
- A scene summary must match the scene text, not the other way round.
- Scene workflow: A read the Map entry and its sequence; B read the Voice Blueprint cards for
  every speaking and shaping silent character; C develop the encounter from what the people
  want; D discuss construction, consequential choices only; E draft against Map and Blueprint
  together; F review the whole scene citing behavior; then Grok's pass.
- After an approved structural change: new Map version, previous preserved, downstream entries
  named. After an approved enduring character change: update the Voice Blueprint. Rulings that
  are not written into a governing document do not survive the session.
- Append 06_Changelog.txt at every step.
- File names: Block_<id>_<title>_DRAFT_<nn>_[WORKING_]NOT_ADOPTED_<date>.txt/.fdx;
  locks Block_<id>_<title>_LOCKED_<date>; audits in 05_Audits as
  Block_<id>_Draft_<nn>_AUDIT_v2_7_HEAT_v5_<date>.txt. Every deliverable also copied to ~/Downloads.

## First actions in a new session
1. Read this file and identify the current version of each governing document by filename.
2. Ask Jason which scene is next. Do not infer it from drafts or the changelog.
3. Read that scene's Map entry and sequence and the Voice Blueprint cards for its characters.
4. Report what the governing documents establish for that scene and any conflict between them.
   Do not draft.
